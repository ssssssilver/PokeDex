# Web 数据治理方案

> 状态：治理 V1 已完成（2026-07-12）。当前实现面向本地 Web 服务，部署阶段可原样迁移到数据库事务。

## 1. 已确认的产品政策

- 商业性质：免费使用，包含广告或赞助，因此按商业用途审查数据。
- 实体卡中文：只有可确认的官方简体中文卡牌才写入中文字段；没有官方简中版本时保留英文。
- 繁体标准：采用台湾官方术语。OpenCC 只作为普通界面文字的回退，不作为宝可梦、招式、卡牌和系列专名的权威来源。
- 当前阶段只改造本地 Web 数据链路，不处理服务器和数据库部署。

## 2. 数据源政策

运行时政策由 `server/data-source-registry.js` 维护，并通过 `GET /api/data-sources` 输出。

数据健康聚合由 `GET /api/data-health` 输出。Web 端在“我的 → 数据来源与声明”公开展示启用状态、许可边界、固定 revision 和版权声明。

| --- | --- | --- | --- |

| 宝可梦 | Project Pokémon | 3D GIF | 默认停用，等待媒体授权确认 |

## 3. 发布流程

同步数据遵循以下顺序：

1. 抓取来源并记录 URL、时间、ETag、哈希和字节数。
2. 在内存或来源快照中规范化，不向页面暴露处理中间态。
3. 执行数量、主键唯一性、必需字段、跨图鉴关联、来源新鲜度和数量突变检查。
4. 质量门禁通过后一次性替换正式目录，并写入 `data_release`。
5. 门禁失败时保留上一发布版本，失败记录写入同步历史。

Pocket 已执行完整流程。PTCG 全量同步会整批抓取后调用 `replaceCatalog`；续传和增量同步会明确标记为 `resume_success` 或 `incremental_success`，不再冒充全量成功。

chase-mew 与 flibustier 当前固定到经过验证的 Git commit，不直接跟随 `main`。升级时先执行契约测试和 Pocket 干运行，再更新 revision。

## 4. 多语言字段

新增数据统一使用以下字段：

```text
name_zh_cn
name_zh_tw
name_en
description_zh_cn
description_zh_tw
description_en
```

为兼容现有页面，迁移期继续保留 `name_zh`。PokeAPI 同步已经分别保存 `zh-hans` 和 `zh-hant` 名称、分类和图鉴描述。实体卡缓存中的 `name_zh` 只有接入经过许可且可验证的官方简中映射后才允许赋值。

实体卡官方简中目录位于 `server/data/ptcg-official-zh-cn.json`。每条记录必须包含官方中文名、官方来源 URL、发布方和审核时间，否则整个目录拒绝加载。V1 初始目录为空，因此当前无官方映射的实体卡完整保留英文。

## 5. 当前质量门禁

### 宝可梦

- 请求范围内摘要和详情必须存在。
- 英文名与中文名不得为空。
- 首轮失败项自动使用更低并发、更长超时再执行一次补偿。
- 仍失败的 ID 写入 `retryQueue`，发布状态标记为 `degraded-fallback`。

### 实体卡

- 全量数量不得低于源站报告数量的 98%。
- ID 必须唯一，名称和缩略图必须存在。
- 与上一发布版本相比，数量变化默认不得超过 20%。
- 全量、续传和增量状态分开记录。

### Pocket

- 卡牌数量不得低于 3000。
- ID 必须唯一，中英文名称和图片必须存在。
- 所有宝可梦卡必须关联全国图鉴编号。
- 10 个启用来源必须全部新鲜，任一来源只能使用旧快照时拒绝发布。
- 与上一版本相比，卡牌数量变化默认不得超过 20%。

## 6. V1 验收结果

- 数据源注册：10 个来源实体，7 个启用，3 个因授权或架构原因停用。
- Pocket：3305 张卡、10 个启用端点，固定 GitHub revision 后干运行通过。
- 跨图鉴：3042 张 Pocket 宝可梦卡全部关联全国图鉴编号，抽样误匹配为 0。
- PTCG：增量同步状态、质量门禁和无 `select` 参数兼容性测试通过。
- 宝可梦：小规模真实同步、失败补偿路径和简繁字段转换测试通过。
- Web：`390x844` 与 `1440x900` 来源页均无横向溢出，三语内容和桌面导航状态正确。
- 自动化：数据治理、来源契约、缓存校验、三类 API、调度器、SEO 与生产构建通过。
