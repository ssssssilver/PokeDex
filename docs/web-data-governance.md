# Web 数据治理方案

## 1. 已确认的产品政策

- 商业性质：免费使用，包含广告或赞助，因此按商业用途审查数据。
- 实体卡中文：只有可确认的官方简体中文卡牌才写入中文字段；没有官方简中版本时保留英文。
- 繁体标准：采用台湾官方术语。OpenCC 只作为普通界面文字的回退，不作为宝可梦、招式、卡牌和系列专名的权威来源。
- 当前阶段只改造本地 Web 数据链路，不处理服务器和数据库部署。

## 2. 数据源政策

运行时政策由 `server/data-source-registry.js` 维护，并通过 `GET /api/data-sources` 输出。

| 产品 | 来源 | 职责 | 当前状态 |
| --- | --- | --- | --- |
| 宝可梦 | PokeAPI | 图鉴主数据与多语言原文 | 启用 |
| 宝可梦 | Project Pokémon | 3D GIF | 默认停用，等待媒体授权确认 |
| 实体卡 | Pokémon TCG API | 英文卡牌、系列、规则与图片 | 启用 |
| 实体卡 | Limitless TCG | 热门卡组统计 | 启用，必须标注第三方来源 |
| 实体卡 | PTCG-CHS-Datasets | 人工术语参考 | 禁止导入和再分发 |
| Pocket | RaenonX | 游戏主数据、活动和中英文词条 | 启用，按非公开接口管理 |
| Pocket | chase-mew | 卡图、英文名称和基础元数据 | 启用 |
| Pocket | flibustier | 系列、稀有度和抽取概率 | 启用 |
| Pocket | Limitless Pocket | 热门卡组统计 | 启用，必须标注第三方来源 |
| Pocket | deckgym-core | 模拟规则 | 核心数据链路停用；未来如做模拟需独立进行 AGPL 审查 |

开源仓库的许可证不自动覆盖其中的 Pokémon 名称、角色、卡图和游戏素材。媒体文件仍需单独保留来源并在正式商业发布前复核。

## 3. 发布流程

同步数据遵循以下顺序：

1. 抓取来源并记录 URL、时间、ETag、哈希和字节数。
2. 在内存或来源快照中规范化，不向页面暴露处理中间态。
3. 执行数量、主键唯一性、必需字段、跨图鉴关联、来源新鲜度和数量突变检查。
4. 质量门禁通过后一次性替换正式目录，并写入 `data_release`。
5. 门禁失败时保留上一发布版本，失败记录写入同步历史。

Pocket 已执行完整流程。PTCG 全量同步会整批抓取后调用 `replaceCatalog`；续传和增量同步会明确标记为 `resume_success` 或 `incremental_success`，不再冒充全量成功。

## 4. 多语言字段

新增数据统一使用以下字段：

```text
name_zh_cn
name_zh_tw
name_en
description_zh_cn
description_zh_tw
description_en
```

为兼容现有页面，迁移期继续保留 `name_zh`。PokeAPI 同步已经分别保存 `zh-hans` 和 `zh-hant` 名称、分类和图鉴描述。实体卡缓存中的 `name_zh` 只有接入经过许可且可验证的官方简中映射后才允许赋值。

## 5. 当前质量门禁

### 宝可梦

- 请求范围内摘要和详情必须存在。
- 英文名与中文名不得为空。
- 首轮失败项自动使用更低并发、更长超时再执行一次补偿。
- 仍失败的 ID 写入 `retryQueue`，发布状态标记为 `degraded-fallback`。

### 实体卡

- 全量数量不得低于源站报告数量的 98%。
- ID 必须唯一，名称和缩略图必须存在。
- 与上一发布版本相比，数量变化默认不得超过 20%。
- 全量、续传和增量状态分开记录。

### Pocket

- 卡牌数量不得低于 3000。
- ID 必须唯一，中英文名称和图片必须存在。
- 所有宝可梦卡必须关联全国图鉴编号。
- 10 个启用来源必须全部新鲜，任一来源只能使用旧快照时拒绝发布。
- 与上一版本相比，卡牌数量变化默认不得超过 20%。

## 6. 后续工作

1. 建立可审计的官方简中实体卡映射库，记录官方系列、卡号、来源页面和审核状态。
2. 将宝可梦的招式、特性、地区和分类逐步补齐独立 `zh-CN`、`zh-TW` 字段。
3. 为 Limitless HTML 解析增加结构契约测试和异常告警。
4. 将 GitHub `main` 数据地址升级为版本标签或经过校验的快照版本。
5. 部署阶段再把相同的 staging/release 模型迁移到 PostgreSQL，不改变前端 API。
