# Web 海外版：国际化、响应式与 SEO 阶段方案

## 1. 阶段目标

Web 版面向海外用户，第一阶段支持 `zh-CN`（简体中文）、`zh-TW`（繁体中文）和 `en`（英文），同时覆盖手机、平板和桌面浏览器。小程序继续冻结在 `miniapp-v1.0.0`，Web 使用 Node 服务端 API，不再依赖静态 OSS API。

本阶段已交付：三语 locale 基础设施、语言持久化、API 语言标识、三类图鉴名称本地化回退、桌面侧栏、移动端语言切换、核心响应式约束、浏览器路由、基础 meta/canonical、`robots.txt` 和 `sitemap.xml`，以及 Pocket 全国图鉴编号修复。

## 2. 当前问题与结论

### 数据国际化

- 宝可梦缓存已有英文、简体、繁体图鉴描述，但部分分类、地区、属性和服务端派生文案仍只有简体。
- 实体 PTCG 以简体翻译和英文原文为主，繁体需要独立术语表，不能直接逐字转换卡牌专名。
- Pocket 的 RaenonX 数据以繁体为主，DeckGym 提供英文规则；简体需要受控术语转换。
- API 当前返回多语言字段，前端按 `zh-CN -> zh-TW -> en` 或 `en -> 原始字段 -> 中文` 回退。后续数据同步应统一为 `name_zh_cn/name_zh_tw/name_en`、`description_*`，避免页面自行猜字段。

### 界面国际化

- 语言优先级：用户保存值 > 浏览器语言 > `zh-CN`。
- locale 使用 BCP 47：`zh-CN`、`zh-TW`、`en`。请求携带 `Accept-Language`。
- 公共导航、命令、状态统一从 `web/src/i18n` 取值；禁止新增硬编码界面文案。
- 英文通常比中文长 30%-80%，按钮、筛选项和卡片标题必须允许换行或省略，不能依赖固定字宽。
- 日期、数字、百分比使用 `Intl.DateTimeFormat`、`Intl.NumberFormat`；不要拼接“只、张、世代”等量词。
- 宝可梦、招式、特性、系列名维护审核过的三语术语表。机器转换只可作为缺失时的临时回退，并记录来源。

## 3. 响应式规则

| 区间 | 导航 | 内容布局 |
| --- | --- | --- |
| `< 768px` | 底部导航 | 单列详情、2-3 列紧凑入口、筛选抽屉 |
| `768-1023px` | 底部导航 | 2-3 列列表、加宽详情 |
| `>= 1024px` | 248px 左侧栏 | 3 列列表、筛选面板、最大 1280px 内容区 |
| `>= 1280px` | 左侧栏 | 图鉴/卡牌列表最多 4 列 |

桌面端不能只是放大的手机页：筛选应常驻或使用宽面板，详情页可以采用“图像/关键数据 + 详细资料”的双栏结构。移动端保留安全区、44px 最小点击目标和底部栏；不把 hover 当作唯一交互，系列名称提示同时支持点击、键盘焦点和无障碍名称。

重点页面规则：

- 图鉴列表：手机单列或双列，桌面 3-4 列；分页/无限加载都必须保持筛选条件。
- 卡牌列表：使用稳定卡图比例，英文长名称最多两行；筛选在手机为抽屉、桌面为侧面板。
- 详情页：手机纵向，桌面双栏；属性相克表在窄屏横向滚动并固定表头。
- 卡组详情：桌面显示卡组统计与卡表并排，手机顺序展示；复制按钮必须有成功/失败反馈。

## 4. SEO 方案

### 已完成的基础能力

- 使用 browser history 路由，服务端对前端路径执行 SPA fallback。
- 首页提供 title、description、keywords、Open Graph 与 theme color。
- 路由切换更新页面标题和 canonical。
- Node 服务提供 `robots.txt` 和包含三类核心图鉴入口的 `sitemap.xml`。
- `/api/` 明确禁止搜索引擎抓取。

### SEO 的真实边界

当前仍是客户端渲染 SPA。meta、sitemap 和干净 URL 能改善发现与分享，但不能保证搜索引擎稳定索引图鉴正文。面向海外正式获客前，必须增加服务端渲染或构建期预渲染：

1. 为 `/zh-cn`、`/zh-tw`、`/en` 建立可抓取语言路径，并输出 `hreflang` 与 `x-default`。
2. 为宝可梦、卡牌、卡组生成稳定语义 URL，例如 `/en/pokemon/charizard`，不要只使用查询参数或内部数字。
3. 服务端输出每个详情页的本地化 title、description、canonical、Open Graph 图片和正文首屏。
4. 增加 `WebSite`、`BreadcrumbList` 和适用的 `ItemList` JSON-LD；不伪造不适用的 Product/Review 数据。
5. sitemap 按语言和内容类型拆分并标注 `lastmod`，数据同步后增量更新。

建议下一阶段采用“Node 服务端模板 + 关键详情页预渲染”，保留 Taro 负责登录后和强交互页面。若自然搜索成为主要获客渠道，再评估迁移公开内容层到支持 SSR/SSG 的 React 框架。

## 5. 实施约束

- 新接口字段必须说明语言、来源与回退顺序。
- 缓存如果按响应语言裁剪，URL 参数优先于 `Vary: Accept-Language`，便于 CDN 正确缓存。
- 用户收藏、队伍和拥有状态存储稳定 ID，绝不存展示名称，切换语言后无需迁移用户数据。
- 本地化内容不得改变搜索主键；搜索索引需要同时纳入三语名称和常见别名。
- 所有图片保留可本地化 `alt`；图标按钮必须有可翻译的无障碍名称。

## 6. 验收矩阵

- Viewport：`390x844`、`768x1024`、`1440x900`。
- 浏览器：Chrome、Edge、Safari/iOS Safari。
- 语言：三种 locale 分别检查首页、三类列表、三类详情、筛选、热门卡组、开包、玩法和“我的”。
- 内容：使用最长英文标题、无翻译字段、空结果、接口失败和慢图片场景。
- SEO：直接访问深层 URL 返回 200；检查 title、description、canonical、robots、sitemap；预渲染上线后用禁用 JavaScript 的抓取结果验收正文。
- 数据：`tools/validate-pocket-cache.js` 的映射差异必须为 0；三类关联卡牌抽样验证 Bulbasaur、Pikachu、Onix、Scyther、Mewtwo。

## 7. 后续优先级

1. 完成全部页面文案键化和三语术语审核。
2. 服务端规范化三语 DTO，补齐实体卡繁体与 Pocket 简体字段。
3. 完成详情页双栏与桌面筛选面板，不再沿用小程序固定尺寸。
4. 建立三语语义 URL 和公开详情页预渲染。
5. 加入 locale × viewport 的视觉回归和无障碍自动化测试。
