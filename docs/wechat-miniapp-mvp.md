# PokeChill 微信小程序 MVP 规格

更新日期：2026-07-06

## 定位

PokeChill 小程序是一款以宝可梦图鉴为基座、扩展轻玩法的微信小程序。

第一版不追求复刻完整对战游戏，而是做一个打开速度快、路径短、适合碎片时间使用的「图鉴工具 + 每日玩法盒子」。

核心循环：

```text
首页发现 -> 查询图鉴 -> 收藏/记录 -> 玩每日挑战 -> 发现新宝可梦 -> 回到图鉴
```

## 工程方向

当前仓库已经收口到微信原生小程序路线：

- 形态：微信小程序，不是小游戏。
- 体验：工具型图鉴 + 轻互动玩法。
- 技术：WXML/WXSS/小程序组件/自有 Node 中转服务；保留云函数方案文档作为备选。
- 目标：更贴合微信小程序的页面结构、Tab 导航、列表、搜索、收藏和分享。

## 设计简报

- 产品：宝可梦图鉴基座 + 多种轻玩法的小程序。
- 视觉方向：贴近微信小程序和 WeUI 习惯，清爽、克制、信息优先；保留一点 PokeChill 的轻松陪伴感。
- 交互深度：MVP 需要真实可用，搜索、筛选、收藏、猜谜、队伍分析都应有完整状态；复杂数据可先用缓存/静态种子数据支撑。
- 首屏原则：首页直接给功能和今日内容，不做网页式宣传落地页。

## 用户画像

### 轻度玩家

想快速查一只宝可梦的属性、进化、基础数值和图片。路径要短，不愿被复杂系统打断。

### 回坑玩家

知道一部分宝可梦，但记不清新世代、属性组合、进化条件和招式信息。需要筛选、对比和收藏。

### 分享型用户

喜欢每日挑战、猜谜、生成卡片，愿意把结果发给朋友或群聊。

## MVP 成功标准

- 用户可以在 3 秒内理解小程序能做什么。
- 用户可以在 2 次点击内进入图鉴搜索。
- 用户可以完成一次「查找 -> 查看详情 -> 收藏」。
- 用户可以完成一次每日猜谜，并看到结果反馈。
- 用户可以选择最多 6 只宝可梦并看到队伍属性弱点概览。
- 常用图鉴数据首屏加载稳定，不依赖实时直连 PokeAPI。

## 底部 Tab

### 首页

定位：今日内容和最高频入口。

内容：

- 今日宝可梦卡片。
- 搜索框入口。
- 今日猜谜入口。
- 最近查看。
- 收藏快捷入口。
- 玩法快捷入口。

页面重点：

- 用户打开后立刻看到一只宝可梦和一个可点的行动。
- 避免大段说明文字。
- 首页像微信小程序工具页，不像营销官网。

### 图鉴

定位：核心查询入口。

内容：

- 搜索框。
- 属性筛选。
- 世代筛选。
- 排序：编号、名称、种族值、收藏。
- 宝可梦列表。

列表项信息：

- 编号。
- 名称。
- 图片。
- 属性标签。
- 收藏按钮。

### 玩法

定位：轻互动集合。

MVP 玩法：

- 猜宝可梦。
- 队伍分析器。
- 随机挑战生成器。
- 属性克制速查。

后续玩法：

- 图鉴成就。
- 每日签到/每日发现。
- 分享卡片生成。
- 宝可梦性格/心情标签。

### 我的

定位：个人数据和设置。

内容：

- 收藏夹。
- 浏览历史。
- 图鉴进度。
- 猜谜记录。
- 缓存/数据版本。
- 关于与免责声明。

## MVP 页面清单

### 1. 首页

入口：

- 小程序默认打开。

核心模块：

- 今日宝可梦。
- 顶部搜索入口。
- 四个功能入口：图鉴、猜谜、队伍、属性。
- 最近查看。

状态：

- 首次打开：展示推荐宝可梦和空历史。
- 已使用：展示最近查看、收藏提示。
- 加载失败：展示本地缓存内容和重试按钮。

### 2. 图鉴列表页

入口：

- 首页搜索。
- 底部 Tab 图鉴。

核心功能：

- 输入中文/英文/编号搜索。
- 按属性筛选。
- 按世代筛选。
- 切换排序。
- 点击进入详情。
- 快速收藏。

MVP 数据：

- 编号。
- 英文名。
- 中文名。
- 图片。
- 属性。
- 世代。
- 基础种族值总和。
- 是否收藏。

### 3. 宝可梦详情页

入口：

- 图鉴列表。
- 首页今日宝可梦。
- 猜谜结果。
- 队伍分析推荐。

信息分区：

- 顶部资料卡：图片、编号、名称、属性、收藏。
- 基础资料：身高、体重、分类、世代。
- 种族值：HP、攻击、防御、特攻、特防、速度。
- 特性：普通特性、隐藏特性。
- 进化链：上一阶段、当前、下一阶段。
- 属性关系：弱点、抗性、免疫。
- 可学招式：MVP 可先只展示前若干常见招式或入口。

操作：

- 收藏/取消收藏。
- 加入队伍分析。
- 分享。

### 4. 猜宝可梦

入口：

- 首页今日挑战。
- 玩法 Tab。

MVP 玩法：

- 每日 1 题。
- 根据剪影、属性、世代、身高/体重或种族值提示来猜。
- 最多 5 次机会。
- 每次猜错增加一个提示。
- 结束后展示详情入口。

状态：

- 未开始。
- 进行中。
- 猜对。
- 猜错用尽次数。
- 今日已完成。

### 5. 队伍分析器

入口：

- 玩法 Tab。
- 详情页「加入队伍分析」。

MVP 功能：

- 最多选择 6 只宝可梦。
- 展示队伍属性构成。
- 展示共同弱点。
- 展示抗性覆盖。
- 给出简单评分。

MVP 规则：

- 只基于属性关系分析。
- 暂不考虑招式、特性、性格、道具和努力值。

输出示例：

- 队伍偏向：水/飞行较多。
- 主要风险：电、岩。
- 建议补位：地面、电、草等候选。

### 6. 我的收藏

入口：

- 我的 Tab。
- 首页收藏入口。

核心功能：

- 查看收藏宝可梦。
- 按属性/世代筛选收藏。
- 移除收藏。
- 进入详情。

## 小程序交互原则

- 使用底部 Tab 承载一级导航。
- 每个页面只保留一个主任务。
- 搜索和筛选放在图鉴页顶部，避免藏在二级菜单。
- 列表项最多保留一个主点击区域和一个收藏操作。
- 加载优先用骨架屏或局部 loading，少用全屏模态 loading。
- 页面文案短，避免解释型大段文字。
- 分享动作放在结果页和详情页，不打扰查询路径。

## 视觉原则

- 字体使用系统默认字体。
- 常用字号：标题 18-24px，正文 14-16px，辅助 12px。
- 间距以 8/12/16px 为基础。
- 卡片圆角克制，建议 8px。
- 主色不要大面积铺满，主要用于关键按钮、选中态和属性高亮。
- 属性标签使用类型色，但列表整体保持白底/浅灰底，避免一屏颜色太吵。
- 首页需要有宝可梦图片作为第一视觉信号。

## 数据方案

### 原则

小程序不要频繁直连 PokeAPI。推荐做自己的缓存层：

```text
PokeAPI -> 同步脚本/后端任务 -> 自有数据库或 JSON 缓存 -> 小程序 API -> 小程序页面
```

原因：

- 小程序需要配置合法请求域名。
- 国内访问 PokeAPI 的速度和稳定性不可控。
- 图鉴数据变化低，适合缓存。
- 玩法需要自己的收藏、历史、每日题目和统计数据。

### MVP 缓存数据

`pokemon_summary`

- id
- name_en
- name_zh
- sprite_url 或 local_asset
- types
- generation
- stat_total

`pokemon_detail`

- id
- names
- types
- height
- weight
- stats
- abilities
- species
- evolution_chain_id
- moves_summary

`evolution_chain`

- id
- nodes
- conditions

`type_relation`

- type
- double_damage_to
- half_damage_to
- no_damage_to
- double_damage_from
- half_damage_from
- no_damage_from

`user_profile`

- openid
- favorites
- recent_views
- quiz_history
- team_slots

### PokeAPI 资源映射

- `pokemon`：基础资料、图片、属性、种族值、特性、招式。
- `pokemon-species`：中文名、多语言名、分类、世代、进化链链接。
- `evolution-chain`：进化链。
- `type`：属性克制关系。
- `ability`：特性名称和说明。
- `move`：招式名称、属性、威力、命中、说明。
- `generation`：世代数据。

## 推荐技术架构

### 前端

- 微信原生小程序。
- WXML/WXSS/JavaScript 或 TypeScript。
- WeUI 风格组件或微信原生组件优先。
- 本地缓存使用 `wx.setStorage` / `wx.getStorage`。

### 后端

MVP 可选两种：

方案 A：微信云开发

- 云函数提供图鉴 API。
- 云数据库存缓存数据。
- 云函数定时同步 PokeAPI。
- 更贴近小程序生态，早期省部署。

方案 B：独立 Node 服务

- Node/Express 或轻量框架。
- SQLite/Postgres 存缓存。
- 定时任务同步 PokeAPI。
- 后续扩展更自由。

建议第一版优先方案 A，除非已经有稳定后端环境。

## API 草案

```text
GET /pokemon?keyword=&type=&generation=&sort=&page=
GET /pokemon/{id}
GET /pokemon/{id}/evolution
GET /types
GET /types/{type}/relations
POST /users/me/favorites/{pokemonId}
DELETE /users/me/favorites/{pokemonId}
GET /users/me/favorites
GET /quiz/daily
POST /quiz/daily/answer
POST /team/analyze
```

## MVP 不做

- 不做完整战斗模拟器。
- 不做账号体系之外的复杂社交。
- 不做实时多人玩法。
- 不做完整招式学习表的复杂筛选。
- 不做商业化。
- 不依赖 PokeAPI 实时请求作为首屏加载链路。

## 风险

### IP 与审核

宝可梦名称、图片和素材涉及 IP 风险。公开发布前需要评估素材来源、展示方式、免责声明和平台审核风险。

### 数据质量

PokeAPI 是优秀的数据源，但中文名、图片、招式说明等字段可能需要补充、校正或本地化。

### 网络稳定性

不要把 PokeAPI 放在用户实时访问链路上。同步失败时应继续使用上一版缓存数据。

### 玩法复杂度

队伍分析第一版只做属性维度，避免一开始陷入正作对战系统的复杂规则。

## 下一步拆工

1. 决定前端技术：微信原生小程序，还是 Taro/uni-app。
2. 决定数据层：微信云开发，还是独立 Node 服务。
3. 建立小程序页面目录和 Tab 配置。
4. 准备前 151 只宝可梦的缓存数据结构。
5. 先做首页、图鉴列表、详情页三页闭环。
6. 再接入收藏、猜谜和队伍分析。

## 当前落地状态

已按「微信原生小程序 + 微信云开发缓存层」建立第一版工程骨架：

- 小程序工程：`wechat-miniapp/`
- 小程序端：`wechat-miniapp/miniprogram/`
- 云函数端：`wechat-miniapp/cloudfunctions/`
- 运行期查询函数：`cloudfunctions/pokedex`
- PokeAPI 同步函数：`cloudfunctions/syncPokeapi`

小程序端默认先使用本地种子数据，方便在微信开发者工具中直接预览。云开发环境部署完成后，用 `tools/configure-miniapp-cloud-local.js` 生成本机私有的 `wechat-miniapp/miniprogram/config.local.js`，再将 `useCloudApi` 切为 `true`。

云开发部署步骤见 `docs/wechat-miniapp-cloud-setup.md`。
